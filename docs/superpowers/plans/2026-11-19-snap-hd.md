# Snap HD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-page iPhone web app (`snap.html`) that converts photos/videos from the photo library to 1080×1920 high-quality files and hands them to Snapchat through the iOS share sheet.

**Architecture:** One self-contained HTML file (the repo's existing pattern), no build step, no network. Pure helpers live on `window.SnapHD` so a Playwright script can test them. Photos: stepwise canvas downscale + light unsharp mask → JPEG. Videos: hidden `<video>` drawn per frame onto a 1080×1920 canvas, `canvas.captureStream` + WebAudio audio track → `MediaRecorder` MP4.

**Tech Stack:** HTML/CSS/vanilla JS; Playwright (pre-installed) + Node for tests.

**Spec:** `docs/superpowers/specs/2026-11-19-snap-hd-design.md`

## Global Constraints
- Output size exactly 1080×1920; JPEG quality 0.95; sRGB canvas.
- Video: H.264 MP4 when `MediaRecorder.isTypeSupported` allows, ~12 Mbps, 30 fps, with audio.
- `index.html` (calendar) is not modified.
- No network requests, no external scripts; everything on-device.
- Arabic RTL UI, ocean theme tokens copied from `index.html`, auto light/dark.
- Home-screen title: "سناب HD".

## Review Focus
1. 24 MP+ Lightroom export (6000×4000) exceeds iOS's ~16.7 MP canvas limit → first downscale step must stay ≤ 16,777,216 px and output still 1080×1920.
2. Landscape or 4:5 photo → auto mode is "fit" (whole image on blurred background), not a brutal crop.
3. Video longer than 60 s → item shows the "سناب بيقسّمه" note.
4. One corrupt file in a batch → that item shows an error, the others still finish.
5. No Web Share support (desktop) → send button falls back to download.

### Task 1: Layout + image pipeline

**Files:** Create `snap.html`; Create `tests/snap.test.mjs`

**Interfaces — Produces on `window.SnapHD`:**
- `TARGET = {w:1080, h:1920}`
- `autoMode(w:number, h:number) -> 'fill'|'fit'` — 'fill' iff 0.5 ≤ w/h ≤ 0.68.
- `planLayout(w, h, mode) -> {sx, sy, sw, sh, dx, dy, dw, dh}` — fill: centered crop of source to 9:16, dest = full target; fit: whole source, dest centered and contained.
- `firstStepSize(sw, sh, dw, dh) -> {w, h}` — largest dw·2^k × dh·2^k ≤ (sw, sh) with area ≤ 16,777,216 (k ≥ 0).
- `processImage(file: File, mode) -> Promise<Blob>` (image/jpeg, 1080×1920).

- [ ] Step 1: tests — `autoMode(1080,1920)==='fill'`, `autoMode(4000,6000)==='fill'`, `autoMode(4000,5000)==='fit'`, `autoMode(6000,4000)==='fit'`; fill plan of 6000×4000 has sw/sh ≈ 0.5625 and dw=1080, dh=1920; fit plan of 6000×4000 has dw=1080, dh=720, dy=600; `firstStepSize(6000,4000,1080,720)` area ≤ 16,777,216; `processImage` on a generated 6000×4000 PNG in each mode decodes to 1080×1920 and type image/jpeg; a text file named bad.jpg rejects.
- [ ] Step 2: run `node tests/snap.test.mjs` → FAIL.
- [ ] Step 3: implement. Decode with `<img>` + `decode()`. Halve repeatedly with `imageSmoothingQuality='high'`. Unsharp mask on the content: amount 0.35, 3×3 box blur. Fit background = image scaled to 27×48 then back up, plus 25% black overlay. Free intermediate canvases (width=0).
- [ ] Step 4: run tests → PASS. Commit.
